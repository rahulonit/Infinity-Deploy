# Installation and configuration

## 1. Preflight checklist

Confirm on both WordPress sites:

- WordPress 6.2+ and PHP 7.4+.
- PHP `ZipArchive` is available.
- The REST API is reachable at `/wp-json/infinity-deploy/v1/status`.
- `wp-content`, its component directories, and the database are writable by WordPress.
- Pretty permalinks can be flushed.
- Loopback HTTP requests to the site itself are allowed.
- The host has enough free disk space for a source export, destination upload, and safety snapshot at the same time.
- PHP and proxy upload limits exceed the largest individual database or component package.

Local must be version 9.0 or later. A Live URL must use HTTPS unless its hostname is `localhost`, `127.0.0.1`, or ends in `.local`.

## 2. Install the WordPress Bridge

Repeat these steps on Local and Live:

1. In WordPress, open **Plugins → Add New → Upload Plugin**.
2. Select `infinity-deploy-bridge.zip`.
3. Choose **Install Now**, then **Activate**.
4. Open **Tools → Infinity Deploy**.
5. Enable **Authenticated deployments**.
6. Set allowed theme slugs as a comma-separated list.
7. Select the post types allowed in selective sync.
8. Set the maximum uploaded package size. The default is 200 MB; this limit does not override a smaller PHP/web-server limit.
9. Set how many theme backups and database snapshots to retain, from 1 to 20.
10. Save.

The status endpoint remains available to an administrator when deployments are disabled so the add-on can explain the connection state. Export and mutation endpoints are blocked while disabled.

## 3. Create dedicated Application Passwords

Repeat on Local and Live:

1. Sign in as the dedicated deployment administrator.
2. Open **Users → Profile**.
3. Find **Application Passwords**.
4. Enter `Infinity Deploy – Local` or `Infinity Deploy – Live` as the name.
5. Choose **Add New Application Password**.
6. Copy the generated value immediately.

The add-on removes spaces from pasted Application Passwords. Use the WordPress username or account email in the username field. A normal account password is intentionally rejected.

For least privilege, use a dedicated account. The current full deployment API requires administrator capabilities (`manage_options`); theme operations additionally require `update_themes` and `install_themes`.

## 4. Install the Local add-on

1. Quit Local completely.
2. Extract `infinity-deploy-local-addon.zip`.
3. Copy the extracted `infinity-deploy-local-addon` folder to the Local add-ons directory:

   - macOS: `~/Library/Application Support/Local/addons/`
   - Windows: `%APPDATA%\Local\addons\`
   - Linux: `~/.config/Local/addons/`

4. Start Local.
5. Enable Infinity Deploy if Local prompts you to enable the add-on.
6. If it does not appear, use Local’s supported development/symlink installation workflow and inspect Local’s add-on logs.

The ZIP’s top-level folder must remain `infinity-deploy-local-addon`; do not copy only its contents into `addons/`.

## 5. Configure a connection

Start the Local site, select it, and open **Tools/Utilities → Infinity Deploy**. Enter:

| Field | Value |
|---|---|
| Local site URL | The exact WordPress home URL, such as `http://project.local` |
| Local WordPress username | Dedicated Local administrator username or email |
| Local Application Password | Password generated by Local WordPress |
| Live site URL | Canonical HTTPS URL; include a WordPress subdirectory if used |
| Live WordPress username | Dedicated Live administrator username or email |
| Live Application Password | Password generated by Live WordPress |
| Theme slug | Theme directory name, not the display name |

Choose **Test both connections**. A successful result reports WordPress versions and the active Live theme version.

## 6. Hosting configuration

For large transfers, review at minimum:

```ini
upload_max_filesize = 512M
post_max_size = 512M
max_execution_time = 600
max_input_time = 600
memory_limit = 512M
```

These are examples, not universal recommendations. Nginx may also require `client_max_body_size`; Apache, a CDN, WAF, load balancer, or managed host may impose separate time/body limits. The add-on uses a ten-minute request timeout, but every network/server layer must allow the request to finish.

## 7. Upgrade

- Bridge: upload the new ZIP and confirm replacement, or deploy through your normal plugin-release channel. Keep the plugin active on both endpoints.
- Local add-on: quit Local, replace the add-on folder, and restart Local.
- Re-test both connections after either component changes.

Saved connection records are retained in Local’s user-data directory when the add-on folder is replaced.

## 8. Uninstall

1. Revoke both WordPress Application Passwords.
2. Disable and delete the Bridge from both sites.
3. Quit Local and remove the add-on folder.
4. Remove the saved connection file if credential removal is required; see [Security and privacy](SECURITY.md#credential-storage).
5. Review and remove retained `.infinity-deploy-backups-*` directories only after confirming no rollback is needed.

Plugin deactivation/deletion intentionally does not delete recovery archives automatically.
